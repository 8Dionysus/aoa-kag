# AOA-KAG-D-0047 Budget Producer Runtime Binding And Descriptor Confinement

## Index Metadata

- Decision ID: AOA-KAG-D-0047
- Original date: 2026-08-25
- Surface classes: schema contract, validation guard, generated budget receipt
- KAG surfaces: repo-local family budget receipt, producer runtime inputs, receipt I/O
- Source lanes: aoa-kag, owner-family validation
- Guard families: runtime provenance, dynamic-input closure, descriptor confinement, fail-closed budget admission
- Posture: accepted

## Context

Independent review found three causal P1 gaps in the current budget admission
boundary: a legacy v1 receipt could still authorize a current tracked-size
exceedance; AST-import closure did not bind dynamic and non-Python execution
inputs; and pathname checks plus final-component `O_NOFOLLOW` remained exposed
to parent replacement between validation and publication.

## Decision

Current admission accepts only the closed v2 top-level receipt shape with the
v3 producer identity. Historical v1 receipts remain retained data, but the
current reader treats them as a non-authorizing quarantine state by rejecting
them before any tracked-size approval check.

The producer identity keeps the reviewed local Python import closure and adds
fail-closed rejection of unresolved dynamic-import calls. It binds the actual
action input values, declared environment states and value digests, resolved
interpreter and dependency artifacts, non-Python schema/action bytes, and
concrete command targets. Sensitive ambient values are represented by state,
size, and content digests; unresolved required inputs fail closed. Producer
commit and tree identities remain outside the receipt to avoid a self-owner
publication cycle.

Receipt reads and writes open the resolved owner root as a directory
descriptor, traverse every parent with `O_NOFOLLOW` and `dir_fd`, and retain
the pinned parent descriptor through the operation. Writes use an exclusive
temporary object, flush and fsync its bytes, atomically rename it within the
pinned parent, and fsync that parent. A parent replacement after traversal
therefore cannot redirect the receipt operation to an external directory.

## Options Considered

- Continue accepting the exact historical v1 shape: rejected because it has no
  current candidate or producer identity and can authorize current tracked
  bytes.
- Treat the reviewed AST closure and declarations as sufficient: rejected
  because dynamic imports, environment values, dependency artifacts, action
  values, and command targets can change without a declaration diff.
- Add more pathname checks or final-file `O_NOFOLLOW`: rejected because a
  checked parent can still be replaced before the later open or write.
- Trace every process and external dependency at arbitrary granularity:
  rejected as non-deterministic and not a stable owner contract; unresolved
  inputs instead fail closed and the admitted runtime contract is explicit.
- Bind the producer commit or candidate tree: rejected because receipt
  publication would reintroduce a self-owner fixed point.

## Consequences

- Existing v1 and pre-repair producer receipts cannot authorize current budget
  exceedance and must be regenerated by the current producer boundary.
- A changed runtime action value, environment value, interpreter, dependency
  artifact, non-Python input, command target, local import, or parent topology
  rejects the receipt or cannot redirect its publication.
- Deterministic negative tests cover legacy admission, dynamic closure,
  runtime-input replay, exact symlinks, and parent replacement.
- Source/CI, owner-family, generated, hosted review, landing, deployment,
  runtime delivery, semantic acceptance, and owner/human acceptance remain
  separate claims owned by their respective lanes.
